Plan: RFFMG-GPT バックエンド追加

Date: 2026-07-09 | Status: approved

概要

RFFMG のフラグメント表現（フラグメント >> 分子 の source→target）を、既存の T5Chem に加えて GPT2 系デコーダ専用モデルでも学習・生成・評価できるようにする。事前学習済み entropy/gpt2_zinc_87m（GPT2, 12層/768/約87M, vocab 2707, n_positions 256）を利用し、 SAFE-GPT(88.8M) と等容量での比較を可能にする。T5Chem と並ぶ MODEL_NAME=gpt バックエンドとして追加する。

確定した決定事項

  • 学習モード: finetuning（ZINC 重み初期化）+ from_scratch（ZINC と同一 config・同一トークナイザ、重み random）の両対応
  • 区切り: >>（元の sentence 形式そのまま）
  • スコープ: 学習・生成・評価までのフルパイプライン
  • 生成スクリプトの統合: gen_t5chem.{py,sh} を gen_rffmg.{py,sh} にリネームし --model_name {t5chem,gpt} で分岐。GPT2 生成本体は src/func/generation_rffmg_func.py
  • HP: run_safe.sh 準拠、LR=1e-4 統一（両モード）、50 epoch、warmup 10000、batch 32、eval/save 5000 step、save_total_limit 5、load_best_model_at_end、wandb offline、seed 固定
  • 実行環境: 既存 t5chem env を流用（transformers 4.45.2 / torch 2.10）。t5chem パッケージは変更しない

データ表現（デコーダ専用化）

  • 学習系列: <bos> + source + ">>" + target + <eos>
  • labels: プロンプト部（<bos>source>>）を -100 マスクし target 部のみ loss（p(target|source)）
  • 生成プロンプト: <bos> + source + ">>" → 続きを生成し >> 以降・eos までを予測分子とする
  • 最大長: 256（n_positions）。train と gen で formatting を厳密一致させる

実装計画

  1. Step 1: GPT2 学習スクリプト新規作成

    対象ファイル: src/train_model/train_gpt.py（新規）

    変更内容: argparse（--frag_method, --mode {finetuning,from_scratch}, --pretrain(既定 entropy/gpt2_zinc_87m), --data_dir, --output_dir 等）。トークナイザは ZINC の AutoTokenizer を両モード共通で使用。finetuning=GPT2LMHeadModel.from_pretrained / from_scratch=GPT2LMHeadModel(GPT2Config(ZINC 同一))。normal/{train,val}.{source,target} から source+">>"+target を作り tokenize（bos/eos 付与, max_length=256）、labels のプロンプト部を -100 マスク。Trainer+TrainingArguments を run_safe.sh 準拠に設定、seed 固定、best_model 保存。

    依存関係: なし（既存 .source/.target を利用、make_datasets 変更不要）

  2. Step 2: 学習ラッパー .sh の MODEL_NAME 分岐

    対象ファイル: src/train_model/run_rffmg.sh（改修）

    変更内容: MODEL_NAME を t5chem|gpt で分岐。gpt は python src/train_model/train_gpt.py --mode $MODE --output_dir models/rffmg/gpt/${MODE}/${FRAG_NAME} を実行し、wandb dir を wandb/rffmg/gpt/${MODE}/${FRAG_NAME} に。既存 t5chem 分岐は温存。

    依存関係: Step 1 の後

  3. Step 3: GPT2 生成本体を func/ に新規作成

    対象ファイル: src/func/generation_rffmg_func.py（新規、generation_safe_func.py と同じ subprocess パターン）

    変更内容: argparse（--model_path, --dataset_file(test.source), --target_file(test.target), --output_dir, --n_samples, --max_length(既定 256), --num_beams, --batch_size, --random_seed）。モデル/トークナイザをロードし、各 source を <bos>source>> にして beam search（num_return_sequences=n_samples）、>> 以降・eos までを予測分子として抽出。predictions.csv を T5Chem と同一列（target, prediction_1..N）で書き出し。

    依存関係: Step 1 の後

  4. Step 4: 生成ラッパーを gen_rffmg に統合（リネーム + model_name 分岐）

    対象ファイル: src/gen_mols/gen_t5chem.py → gen_rffmg.py、gen_t5chem.sh → gen_rffmg.sh（リネーム+改修）

    変更内容: --model_name {t5chem,gpt}（既定 t5chem）を追加。model_path=models/rffmg/{model_name}/{model_ver}/{frag}/best_model、出力=results/rffmg/{model_name}/{model_ver}/{frag}/beam/{additional_path}/predictions.csv。t5chem → 既存 t5chem predict／gpt → python src/func/generation_rffmg_func.py。gen_rffmg.sh に MODEL_NAME 変数を追加。

    依存関係: Step 3 の後

  5. Step 5: 評価スクリプトの GPT 対応

    対象ファイル: src/evaluation.py（改修）

    変更内容: --model_name に gpt を追加。str_name/model_dir の 2 値分岐を 3 値化（gpt → str_name='rffmg', model_dir='gpt', 入力は test.source）。loadTrainSmiles/loadGenSmiles へは arc_name='t5chem' 相当を渡し既存分岐を再利用（evaluation_func.py は無改修）。

    依存関係: Step 4 の後

  6. Step 6: 作図スクリプトの GPT 対応

    対象ファイル: src/figure.py（改修）

    変更内容: arc_name（現状 't5chem' ハードコード）に rffmg+gpt を扱えるようパス生成を対応（results/rffmg/gpt/...・figures/.../rffmg/gpt/...）。

    依存関係: Step 5 の後

  7. Step 7: 動作確認（debug スモーク）+ ドキュメント更新

    対象ファイル: README.md / README_ja.md / .claude/structure.md（改修）

    変更内容: normal/debug の少量データで train_gpt.py → gen_rffmg.py(gpt) → evaluation.py を 1 回通し、パス・CSV 形式・系列長(256 内)を確認。README/structure に GPT バックエンドと gen_rffmg リネームを追記。

    依存関係: Step 6 の後

変更しないもの（再利用）

  • src/func/evaluation_func.py（t5chem 分岐を再利用）

リスク / 留意

  • n_positions=256: normal データは concat max 217 で収まる。将来の長い評価スライス生成時は要再確認
  • from_scratch はランダム初期化のため 50 epoch で収束するか要観察（HP 探索はしない方針）
  • 生成の formatting（bos / >> / eos）を train と gen で厳密一致させること
  • gen_t5chem → gen_rffmg リネームに伴う参照箇所（README 等）を追随更新
