Plan: PromptSMILES をベースラインモデルとして追加

Date: 2026-07-23 | Status: pending-approval

概要

PromptSMILES (Thomas et al., J. Cheminform. 2024) をベースラインモデルとして本プロジェクトに組み込む。 PromptSMILES 自体は「制約付き生成（scaffold decoration / fragment linking）を再学習なしで行う推論時プロンプト手法」だが、 公平な比較のためにはベースとなる化学言語モデル（prior）を既存モデルと同一の ChEMBL31 コーパスで再学習する必要がある。

  • ベースCLMアーキ: GTr（StableTransformerEncoder。RFFMG-GPT(GPT2) と系統を揃え比較しやすくするため）
  • 評価タスク: Scaffold decoration + Fragment linking
  • 実行環境: 新規 conda 環境 env_promptsmiles（既存 env との依存衝突回避）
  • 外部パッケージ smiles-rnn / promptsmiles（いずれも MIT）を利用し、本リポジトリには既存構成に合わせた薄いラッパーのみ追加する。

タスク入力のマッピング方針: 既存の RFFMG/SAFE 比較と条件を揃えるため、評価用スキャフォールド／フラグメントは テストセット分子から既存の src/func/fragmentation.py を用いて生成し、PromptSMILES の記法（結合点を *、 フラグメント区切りを .）に変換する。

実装計画

  1. Step 1: 新規 conda 環境のセットアップ手順を追加

    対象ファイル: src/train_model/setup_promptsmiles_env.sh（新規）

    変更内容: conda create -n env_promptsmiles python=3.11 → pip install smiles-rnn promptsmiles molscore → torch(cu128)/rdkit/pandas/numpy をスクリプト化。用途・GPU前提をコメント明記。

    依存関係: なし

  2. Step 2: 学習コーパスの書き出しスクリプト

    対象ファイル: src/make_promptsmiles_corpus.py（新規）

    変更内容: data/curated/passed_filters_rdkit_canonical_smiles.tsv の rdkit_washed_smiles 列を読み込み、RDKit None チェック→重複除去→random_state=42 で train/val/test 分割し data/promptsmiles/{train,val,test}.smi を出力。件数ログ保存。型ヒント・Google style docstring 付与。

    依存関係: なし

  3. Step 3: prior 学習ラッパースクリプト

    対象ファイル: src/train_model/run_promptsmiles.sh（新規）

    変更内容: run_safe.sh の作法に倣い、train_prior.py GTr -i .../train.smi --valid_smiles .../val.smi -o models/promptsmiles/gtr -s chembl31 --grammar SMILES --randomize --device gpu を実行。ハイパラは上部変数化・ログ化。

    依存関係: Step 1, Step 2 の後

  4. Step 4: 生成スクリプト（scaffold decoration / fragment linking）

    対象ファイル: src/gen_mols/gen_promptsmiles.py + gen_promptsmiles.sh（新規）

    変更内容: 学習済み prior をロードし promptsmiles の ScaffoldDecorator/FragmentLinker に sample_fn/evaluate_fn を渡して生成。--task {scaffold,linking}, --frag_method, --n_samples, --random_seed 42 を引数化。結果を evaluation.py が読める形式で保存。

    依存関係: Step 3 の後

  5. Step 5: 評価パイプラインへの統合

    対象ファイル: src/evaluation.py（+ 必要なら src/func/evaluation_func.py）

    変更内容: --model_name に promptsmiles を追加し分岐・出力読み取りを配線。validity / uniqueness / novelty / reconstruction を RFFMG・SAFE と同一関数で算出。

    依存関係: Step 4 の後

  6. Step 6: 再現性・ログの担保（横断）

    対象ファイル: Step 2–5 の各スクリプト

    変更内容: set_seed(42)、乱数シード明示、ハイパラ・メトリクスのログ保存、wandb offline ディレクトリ分離、データパスの Path 化。

    依存関係: Step 2–5 に内包

補足・確認事項

  1. 学習エポック/バッチ: 既存 SAFE は 50 epoch。prior の妥当な epoch 数を決定（暫定 10〜50）。
  2. GPU/学習時間: 約188万件コーパスでの Transformer prior 学習は数時間規模。実行タイミング要相談。
  3. 評価スキャフォールド集合: 論文の 17 スキャフォールドか本プロジェクトのテスト分子由来か。本計画は後者（比較整合性重視）を採用。
